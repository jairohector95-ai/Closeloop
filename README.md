# CloseLoop

**Stop losing jobs because you forgot to follow up.**

CloseLoop is a simple SaaS for contractors and small service businesses. You add an estimate you've already sent; CloseLoop follows up with the customer on a schedule (day 2, 5 and 10 by default) in your voice, and stops the moment they reply.

This repository contains the **Phase 1 local MVP**: the full product experience running on your machine with simulated email delivery and browser-local persistence. No accounts, payments, domains or paid APIs are required.

## Run it

Requires Node.js 20 or newer.

```bash
npm install
npm run dev
```

Open **http://localhost:3000**.

Other commands:

| Command              | What it does                                   |
| -------------------- | ---------------------------------------------- |
| `npm run build`      | Production build (also type-checks)            |
| `npm start`          | Serve the production build                     |
| `npm test`           | Run the business-logic test suite (Vitest)     |
| `npm run lint`       | ESLint                                         |
| `npm run typecheck`  | TypeScript only                                |

## What's in Phase 1

- **Marketing site** at `/` with hero, problem, solution, how it works, live example emails, benefits, pricing, FAQ and CTA.
- **Onboarding** at `/onboarding`: business name, your name, email, trade, email tone, with a live preview.
- **Dashboard** at `/dashboard`: quotes awaiting response, follow-ups scheduled, replies, jobs won, total quote value, recovered revenue, "up next" list and recent activity.
- **Quotes** at `/quotes`: searchable, filterable pipeline (Follow-up scheduled, Awaiting reply, Replied, Won, Lost, Paused).
- **Add / edit quote** at `/quotes/new` and `/quotes/[id]/edit` with validation and a live first-email preview.
- **Quote detail** at `/quotes/[id]`: full history, upcoming follow-ups with email previews, and actions (replied, won, lost, pause, resume, reopen, edit, delete).
- **Automation simulator** on the dashboard: *Run automation* processes anything due today; *Simulate next day* and *Skip a week* step a simulated calendar forward one day at a time, running the engine each day.
- **Settings** at `/settings`: business profile, default schedule, default tone, email preview and signature, billing and integrations placeholders, demo-data controls.
- **Owner admin** at `/admin`: users, MRR, trial/paid, conversion, active quotes, follow-ups sent, jobs recovered (local demo data).
- **Demo data**: a dozen fictional quotes in every status, generated by replaying the real engine so history is always consistent. Remove or reload from Settings.

## How the follow-up logic works

All business rules live in `src/lib/domain/` as pure functions with no UI or storage dependencies:

- `quotes.ts`: add / update / delete, schedule normalization, follow-up generation.
- `status.ts`: replied / won / lost / pause / resume / reopen transitions. Every stopping status cancels pending follow-ups; pause keeps them and resume shifts overdue ones forward while preserving spacing.
- `automation.ts`: `selectDueFollowUps` → `claimFollowUp` → `recordDelivery` / `recordFailure`. A follow-up never fires early, is claimed exactly once (so two job runs cannot both send it), retries transient provider failures with backoff, and is skipped when the quote is replied / won / lost / paused. `runAutomation` is the synchronous simulator built from the same pieces.
- `replies.ts`: matches an inbound email to a quote (In-Reply-To / References → thread id → sender) and stops the sequence.

`src/lib/jobs/sweep.ts` is the production job that a cron will call; it uses the same functions across a real email provider and a database repository.

Tests for all of the above are in `src/tests/` (`npm test`).

## Architecture (ready for Phase 2)

```
src/
  app/                 Next.js App Router pages
    (app)/             Authenticated product (dashboard, quotes, settings)
    onboarding/, admin/, page.tsx (marketing)
  components/
    ui/                Design system primitives (Button, Card, Field, Modal, Toast…)
    app/               Product components (QuoteForm, Timeline, AutomationPanel…)
    marketing/         Landing page sections
  lib/
    types.ts           Data model: User, Business, Customer, Quote, FollowUp,
                       TimelineEvent, Settings, Subscription
    constants.ts       Pricing plans, tones, business types, defaults
    domain/            Pure business logic (see above)
    email/
      templates.ts     Tone-based email templates
      generator.ts     EmailGenerator interface (swap in OpenAI later)
      provider.ts      EmailProvider: Simulated (default), Resend, Postmark
    jobs/              JobScheduler interface; runFollowUpSweep (the cron job)
    persistence/       localStorage adapter; WorkspaceRepository + change-set diffing
    integrations/
      inbound.ts       Postmark / Resend inbound webhook normalizers
      mailbox/         Gmail + Microsoft Graph adapters, OAuth + PKCE helpers, MIME builder
    config/env.ts      Server configuration (all optional)
    store/             Zustand store wiring domain + persistence for the UI
    demo/              Demo data generated by replaying the engine
    metrics.ts         Dashboard and admin metrics
    validation.ts      Form validation
  tests/               Vitest suites
supabase/migrations/   Postgres schema for Phase 2
```

The seams for Phase 2 are explicit:

| Phase 2 need                 | Where it plugs in                                                    |
| ---------------------------- | -------------------------------------------------------------------- |
| Supabase / Postgres          | Implement `WorkspaceRepository` (`persistence/repository.ts`) over the schema in `supabase/migrations` |
| Authentication               | `components/app/AppGate.tsx` (currently checks for a local account)  |
| Stripe subscriptions         | `Subscription` model already exists with Stripe id fields; `constants.ts` holds plans |
| Real email (Resend/Postmark) | Adapters exist in `email/provider.ts`; set `EMAIL_PROVIDER` + key    |
| Inbound reply detection      | Webhook → `integrations/inbound.ts` → `domain/replies.ts`             |
| Gmail / Outlook connections  | `integrations/mailbox/*` (adapters written; needs app registrations)  |
| OpenAI personalization       | Implement `EmailGenerator` in `email/generator.ts`                   |
| Scheduled background job     | Cron → `jobs/sweep.ts` (`runFollowUpSweep`) every 15 minutes          |

## Phase 1 limitations

- Data lives in the browser's localStorage. Clearing site data resets the app.
- Emails are simulated. Nothing is sent; the "sent" email is stored on the follow-up so you can review it.
- There is one local account; `/admin` is not protected.
- Pricing is provisional and no payment is collected.
